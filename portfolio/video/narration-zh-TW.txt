第一幕。排班不只是把班次放進日曆。跨夜班、休息時間、有效期費率、工時與薪資估算都必須能重算。ShiftMate 把事實留給確定性的程式；語言模型不計薪、不執行 SQL，也不決定哪筆班次是真的。畫面全部來自版本化合成資料。

第二幕。模型辨識不會永遠正確。合成班表影像由 Gemini 轉成候選資料，再進入草稿。Schema validation 攔下遺漏時間、不合法日期與模糊內容。使用者檢查來源、編輯並逐筆確認後，系統才寫入班表。模型輸出永遠不是已確認班次。

第三幕。問到規章時，只檢索目前使用者的文件片段。答案附上文件與頁碼；相關度不足、版本衝突或證據不足時，系統會拒答。LangGraph 先路由，再選擇班表、規章、混合或不支援路徑，最後驗證證據。工時、薪資與連續工作日仍由程式計算。

第四幕。資料庫請求使用已驗證身分，並由 PostgreSQL Row Level Security 隔離。MCP 只有六個唯讀工具，不接受 owner ID、SQL 或寫入。Google Calendar 使用最小權限、加密 token 與冪等識別碼；失敗時班表不變，仍可匯出 ICS。GitHub 透過受限的 WIF 部署到 Cloud Run，不保存 JSON 金鑰。

第五幕。作品集也展示失敗。離線合成評估中，OCR 九例有三個失敗；RAG 五例有一個衝突失敗；路由十二例有兩個保守回退。可重跑結果只是方向性證據，不是正式人資、法律或 production accuracy 宣稱。公開導覽不登入、不查正式資料、不呼叫 Gemini 或 Calendar，也沒有寫入按鈕。請從原始碼、OpenAPI、測試與部署政策檢查完整取捨。
